# Коллапс мод в GAN: синтетика и Fashion-MNIST

Учебный эксперимент: два GAN с **одинаковым критиком** и разными функциями потерь (обычный BCE
против WGAN-GP со штрафом за градиент) обучаются на двух масштабах — на 8 гауссианах по кругу
(там видно, какие моды теряются) и на Fashion-MNIST (там видно, к чему это приводит на настоящих
картинках). Результат упакован в один короткий ноутбук, который обучает всё сам: гиперпараметры
вынесены в конфиг-ячейку, на каждую эпоху печатается строка метрик, в конце строятся кривые,
монтаж сэмплов и таблица сверки с эталонными прогонами.

Ключевой вывод: при **равной ёмкости критика** (D/G = 1.486, 1 129 345 против 759 873
параметров, без BatchNorm) BCE-плечо коллапсирует — до 40 % сэмплов достаётся одному классу
одежды, четыре класса гаснут ниже 1 %, — а WGAN-GP с тем же критиком держит покрытие 1.00.
То есть причина коллапса здесь в цели обучения, а не в перевесе дискриминатора.

## Что внутри

| Путь | Назначение |

| `src/ganlib.py` | общая библиотека: модели G и D/критика, загрузка Fashion-MNIST, метрики мод (разметчик + k-means-покрытие), штраф за градиент, эталонный цикл обучения |
| `src/toy8.py` | синтетика: 8 гауссиан по кругу, BCE и WGAN-GP, метрики покрытия мод |

## Результаты

Fashion-MNIST, критик один и тот же, различается только цель обучения (сид 42):

| плечо | эпох | доля топ-класса | покрытие мод | H классов | intra | margin D | FID |
|---|---|---|---|---|---|---|---|
| BCE — прогон в ноутбуке | 80 | 0.398 | 0.65 | 0.690 | 14.54 | 24.37 | 84.9 |
| BCE — эталон `fashion_strongD`, для сравнения бюджетов | 40 | 0.341 | 0.80 | 0.745 | 15.81 | 19.35 | 141.0 |
| WGAN-GP — прогон в ноутбуке | 80 | 0.131 | 1.00 | 0.992 | 18.41 | 2.44 | 32.1 |
| WGAN-GP — эталон `fashion_strongD_wgan`, для сравнения бюджетов | 40 | 0.125 | 1.00 | 0.996 | 19.15 | 2.86 | 43.8 |

BCE-плечо на 80 эпохах воспроизводит эталон `fashion_strongD_80ep` без расхождений (max |Δ| = 0
по всем метрикам на всех 80 эпохах, FID совпал до 0.01), WGAN-GP сходится с эталоном с точностью
до ~1e-3 по первым 40 общим эпохам — подробности в «Ограничениях» ноутбука.

Порог шума FD(real↔real) = 5.10, так что FID различает эти плечи уверенно. Критерий коллапса
зафиксирован заранее: доля топ-класса ≥ 0.35 **или** покрытие ≤ 0.75.

Синтетика (8 гауссиан, 5000 шагов генератора): BCE покрывает 7 из 8 мод и отдаёт крупнейшей
0.425 сэмплов, 0.181 точек не попадают ни в одну моду; WGAN-GP покрывает 8 из 8 при 0.139 у
крупнейшей.

## Как воспроизвести

Ноутбук обучает синтетику (~1.5 мин) и оба плеча Fashion-MNIST (~1 ч 45 мин на Apple MPS:
≈24 с на эпоху у BCE и ≈42 с у WGAN-GP, потому что штраф за градиент — это второй backward). Параметр
`TRAIN = False` в конфиг-ячейке переключает ноутбук на чтение готовых историй из
`artifacts/fashion/` — тогда всё исполняется за секунды.

    python -m venv .venv && . .venv/bin/activate
    pip install -r requirements.txt

    export MPLCONFIGDIR="$PWD/.mplconfig" IPYTHONDIR="$PWD/.jupyter" TORCH_HOME="$PWD/data/torch_home"

    python src/toy8.py                    # синтетика отдельно (пишет artifacts/toy8/)
    python src/build_notebook_short.py    # сборка ноутбука из исходников ячеек
    python -m nbconvert --to notebook --execute --inplace \
        --ExecutePreprocessor.kernel_name=python3 \
        --ExecutePreprocessor.timeout=10800 notebooks/mode_collapse_gan.ipynb

Быстрая проверка пайплайна: `EPOCHS = EPOCHS_WGAN = 3` в конфиг-ячейке (или
`python src/build_notebook_short.py --quick` перед сборкой) — около 4 минут.

### Данные

Fashion-MNIST в репозиторий не входит. Первый запуск скачает его через `torchvision` в
`artifacts/data/` (~30 МБ) и соберёт кэш-тензор обучающей части (179 МБ) — это самая долгая
операция первого запуска, дальше она не повторяется. Если данные уже лежат локально, их можно
подложить в `artifacts/data/FashionMNIST/raw/`.

## Оговорки

* **Один сид на плечо** (0 на синтетике, 42 на Fashion-MNIST): межсидовый разброс не измерен,
  все утверждения — про этот сид.
* **Сверка с эталоном — это проверка пайплайна, а не независимая репликация.** BCE-плечо
  воспроизводит `artifacts/fashion/` эпоха за эпохой без расхождений; WGAN-GP на MPS совпадает
  до последнего знака только в процессе, где до него не было другой работы на GPU, иначе
  расходится детерминированно на ~1e-3 (подробности в «Ограничениях» ноутбука).
* **FID** считается на 28×28 в оттенках серого, растянутых до 299×299 RGB, поэтому абсолютные
  значения несравнимы с публикуемыми — сравнимы только эти плечи между собой и с порогом шума.
* **Ячейка WGAN-GP × BatchNorm** не считалась: BN-плечо есть только для BCE, проверяются два
  фактора (функция потерь и бюджет), а не полная матрица 2×2.

## Окружение

Python 3.15.2, torch 2.15.0 (MPS), torchvision 0.29.2, numpy 2.5.4, matplotlib 3.11.2,
pytorch-fid 0.3.0, nbformat 5.11.1, nbconvert 7.17.2. Полный список — `requirements.txt`.
Обучение шло на Apple Silicon MPS; на CPU те же прогоны заметно медленнее (см. историю в
`artifacts/`), на CUDA числа будут другими — сид фиксирует поток, но не арифметику железа.
