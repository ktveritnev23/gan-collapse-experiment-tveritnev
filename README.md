# Коллапс мод в GAN: синтетика и Fashion-MNIST

Учебный эксперимент: два GAN с **одинаковым критиком** и разными функциями потерь (обычный BCE
против WGAN-GP со штрафом за градиент) обучаются на двух масштабах — на 8 гауссианах по кругу
(там видно, какие моды теряются) и на Fashion-MNIST (там видно, к чему это приводит на настоящих
картинках). Результат упакован в один короткий ноутбук, который обучает всё сам: гиперпараметры
вынесены в конфиг-ячейку, на каждую эпоху печатается строка метрик, в конце строятся кривые,
монтаж сэмплов и таблица сверки с эталонными прогонами.

Ключевой вывод: при **равной ёмкости критика** (D/G = 1.486, 1 129 345 против 759 873
параметров, без BatchNorm) BCE-плечо коллапсирует — до 40 % сэмплов достаётся одному классу
одежды, четыре класса гаснут ниже 1 %, — а WGAN-GP с тем же критиком держит покрытие 1.00.
То есть причина коллапса здесь в цели обучения, а не в перевесе дискриминатора.

## Что внутри

| Путь | Назначение |
|---|---|
| `notebooks/mode_collapse_gan.ipynb` | короткий отчёт: синтетика + Fashion-MNIST, оба плеча обучаются в ноутбуке, 18 ячеек |
| `notebooks/mode_collapse_gan_seeds.ipynb` | повтор того же эксперимента на трёх сидах (42/43/44) с усреднением; обучается на GPU через ROCm/CUDA |
| `src/ganlib.py` | общая библиотека: модели G и D/критика, загрузка Fashion-MNIST, метрики мод (разметчик + k-means-покрытие), штраф за градиент, эталонный цикл обучения, выбор устройства (CUDA/ROCm/MPS/CPU) |
| `src/toy8.py` | синтетика: 8 гауссиан по кругу, BCE и WGAN-GP, метрики покрытия мод, прогон по нескольким сидам |
| `src/fid.py` | FID: признаки InceptionV3 из `pytorch_fid` + расстояние Фреше, кэш статистик |

| `src/build_notebook_seeds.py` | сборка ноутбука на трёх сидах; `--finalize` запекает числа из `artifacts/notebook_seeds_run/run.json` в прозу, не перезапуская обучение |

## Результаты

Fashion-MNIST, критик один и тот же, различается только цель обучения (сид 42):

| плечо | эпох | доля топ-класса | покрытие мод | H классов | intra | margin D | FID |
|---|---|---|---|---|---|---|---|
| BCE — прогон в ноутбуке | 80 | 0.398 | 0.65 | 0.690 | 14.54 | 24.37 | 84.9 |
| BCE — эталон `fashion_strongD`, для сравнения бюджетов | 40 | 0.341 | 0.80 | 0.745 | 15.81 | 19.35 | 141.0 |
| WGAN-GP — прогон в ноутбуке | 80 | 0.131 | 1.00 | 0.992 | 18.41 | 2.44 | 32.1 |
| WGAN-GP — эталон `fashion_strongD_wgan`, для сравнения бюджетов | 40 | 0.125 | 1.00 | 0.996 | 19.15 | 2.86 | 43.8 |

BCE-плечо на 80 эпохах воспроизводит эталон `fashion_strongD_80ep` без расхождений (max |Δ| = 0
по всем метрикам на всех 80 эпохах, FID совпал до 0.01), WGAN-GP сходится с эталоном с точностью
до ~1e-3 по первым 40 общим эпохам — подробности в «Ограничениях» ноутбука.

Порог шума FD(real↔real) = 5.10, так что FID различает эти плечи уверенно. Критерий коллапса
зафиксирован заранее: доля топ-класса ≥ 0.35 **или** покрытие ≤ 0.75.

Синтетика (8 гауссиан, 5000 шагов генератора): BCE покрывает 7 из 8 мод и отдаёт крупнейшей
0.425 сэмплов, 0.181 точек не попадают ни в одну моду; WGAN-GP покрывает 8 из 8 при 0.139 у
крупнейшей.

## Повтор на трёх сидах (ROCm/CUDA)

`notebooks/mode_collapse_gan_seeds.ipynb` повторяет тот же эксперимент, но каждое плечо
обучается заново на трёх сидах — 42, 43, 44 (42 — исходный, 43/44 проверяют, не было ли это
везением одного запуска) — и все метрики приводятся как среднее ± std по сидам. Прогон
выполнен на AMD Radeon RX 7900 XTX (gfx1100) через ROCm, 80 эпох на плечо, тот же критик
и те же функции потерь, что в основном ноутбуке.

| плечо | доля топ-класса | покрытие мод | H | intra | margin D | FID | сидов с коллапсом |
|---|---|---|---|---|---|---|---|
| BCE | 0.390 ± 0.048 | 0.68 ± 0.06 | 0.721 ± 0.091 | 14.1 ± 0.3 | 22.9 ± 4.0 | 79.1 ± 5.6 | 3 из 3 |
| WGAN-GP | 0.128 ± 0.008 | 1.00 ± 0.00 | 0.996 ± 0.002 | 18.8 ± 0.1 | 2.4 ± 0.0 | 31.0 ± 1.1 | 0 из 3 |

Разрыв между плечами больше межсидового разброса: у BCE std доли топ-класса 0.048 при среднем
0.390, у WGAN-GP — 0.008 при 0.128. Критерий коллапса (доля топ ≥ 0.35 **или** покрытие ≤ 0.75)
на финальной эпохе выполняется у всех трёх BCE-сидов и ни у одного WGAN-GP-сида; по эпохам он
держится у BCE в 78 ± 19 % эпох, у WGAN-GP — в 0 ± 1 %. Сид 42 воспроизводит исходный прогон
качественно: BCE 0.431 / 0.65 против 0.398 / 0.65 в односидовом ноутбуке на MPS, WGAN-GP
0.120 / 1.00 против 0.125 / 1.00 (там 40 эпох).

Синтетика (5000 шагов, 3 сида): BCE покрывает 7.67 из 8 мод (по сидам 8, 7, 8), крупнейшая мода
0.238 ± 0.089, вне мод 0.145 ± 0.067; WGAN-GP — 6.33 из 8 (по сидам 3, 8, 8), топ
0.240 ± 0.178, вне мод 0.393 ± 0.402. На кольце один из трёх WGAN-GP-сидов не сошёлся
(3 из 8 мод, 0.854 точек вне мод), поэтому вывод об устойчивости WGAN-GP на синтетике тремя
сидами не подкрепляется — в отличие от Fashion-MNIST, где разделение плеч устойчиво.

## Как воспроизвести

Ноутбук обучает синтетику (~1.5 мин) и оба плеча Fashion-MNIST (~1 ч 45 мин на Apple MPS:
≈24 с на эпоху у BCE и ≈42 с у WGAN-GP, потому что штраф за градиент — это второй backward). Параметр
`TRAIN = False` в конфиг-ячейке переключает ноутбук на чтение готовых историй из
`artifacts/fashion/` — тогда всё исполняется за секунды.

    python -m venv .venv && . .venv/bin/activate
    pip install -r requirements.txt

    export MPLCONFIGDIR="$PWD/.mplconfig" IPYTHONDIR="$PWD/.jupyter" TORCH_HOME="$PWD/data/torch_home"

    python src/toy8.py                    # синтетика отдельно (пишет artifacts/toy8/)
    python src/build_notebook_short.py    # сборка ноутбука из исходников ячеек
    python -m nbconvert --to notebook --execute --inplace \
        --ExecutePreprocessor.kernel_name=python3 \
        --ExecutePreprocessor.timeout=10800 notebooks/mode_collapse_gan.ipynb

Быстрая проверка пайплайна: `EPOCHS = EPOCHS_WGAN = 3` в конфиг-ячейке (или
`python src/build_notebook_short.py --quick` перед сборкой) — около 4 минут.

### ROCm (AMD GPU)

Проверено на RX 7900 XTX (gfx1100), Arch, системный ROCm 10.1 и колёса PyTorch для ROCm 7.2.
Колёса несут собственные ROCm-библиотеки, поэтому системный ROCm нужен только для драйвера
(`/dev/kfd`, `/dev/dri`).

    python3 -m venv .venv-rocm && . .venv-rocm/bin/activate
    pip install -r requirements-rocm.txt
    python -m ipykernel install --prefix "$PWD/.venv-rocm" --name rocm

    export GAN_DEVICE=cuda                 # необязательно: cuda/rocm, mps, cpu
    export HSA_TOOLS_DISABLE_REGISTER=1    # обход segfault в rocprofiler-sdk, ROCm issue #5071
    export MIOPEN_FIND_MODE=FAST           # иначе MIOpen ищет алгоритмы на каждом шаге
    export MIOPEN_USER_DB_PATH="$PWD/.miopen-db" MIOPEN_CUSTOM_CACHE_DIR="$PWD/.miopen-cache"
    export TORCH_HOME="$PWD/.torch_home"   # кэш весов InceptionV3

    python src/build_notebook_seeds.py     # ноутбук с тремя сидами
    python -m nbconvert --to notebook --execute --inplace \
        --ExecutePreprocessor.kernel_name=rocm \
        --ExecutePreprocessor.timeout=18000 \
        notebooks/mode_collapse_gan_seeds.ipynb

Полный прогон 80/80 × 3 сида на 7900 XTX занимает около 1 ч 20 мин (BCE ≈6 с/эпоху,
WGAN-GP ≈12 с/эпоху). Чекпоинты пишутся каждые 5 эпох, поэтому прерванный прогон
продолжается с места остановки: `RESUME = True` в конфиг-ячейке, повторный запуск nbconvert
подхватит `artifacts/notebook_seeds_run/`.

Что именно добавлено для ROCm:

* `ganlib.resolve_device()` / `ganlib.device_report()` — единый выбор устройства: `cuda`
  (на AMD это HIP, `torch.cuda.is_available()` возвращает True), затем MPS, затем CPU;
  переопределяется `GAN_DEVICE` или аргументом `--device`. `toy8.py` и ноутбук берут
  устройство оттуда.
* `ganlib.FastConv2d` — свёртка через `unfold + linear` с теми же параметрами. Штраф за
  градиент требует второго backward, и на ROCm путь MIOpen для него стоит ~80 мс на двойной
  backward в штрафе против ~12 мс у GEMM-пути; на CUDA/MPS/CPU используется штатный `nn.Conv2d`.
  Математически это та же свёртка (проверено: max |Δ| = 9e-7 на выходе при тех же весах).
* `requirements-rocm.txt` — torch 2.14.1+rocm7.2 / torchvision 0.29.1+rocm7.2 и остальные
  зависимости.

## Оговорки

* **Основной ноутбук — один сид на плечо** (0 на синтетике, 42 на Fashion-MNIST): там
  межсидовый разброс не измерен, все утверждения — про этот сид. Повтор на трёх сидах
  (`mode_collapse_gan_seeds.ipynb`) как раз закрывает этот пробел, но трёх точек мало:
  std показывает масштаб разброса, а не доверительный интервал.
* **ROCm-числа не бит-в-бит совпадают с MPS-эталоном.** Сид 42 на ROCm даёт BCE 0.431 / 0.65
  против 0.398 / 0.65 в эталоне: другая карта, другие ядра, другой порядок суммирования
  (включая `FastConv2d`). Качественный вывод — BCE коллапсирует, WGAN-GP нет — держится на
  всех трёх сидах, а не на совпадении последних знаков.
* **Синтетика на трёх сидах нестабильна у WGAN-GP**: один из трёх прогонов покрыл 3 из 8 мод.
  Это ограничение бюджета/сидов, а не опровержение результата на Fashion-MNIST.
* **Сверка с эталоном — это проверка пайплайна, а не независимая репликация.** В основном
  ноутбуке BCE-плечо воспроизводит `artifacts/fashion/` эпоха за эпохой без расхождений; WGAN-GP на MPS совпадает
  до последнего знака только в процессе, где до него не было другой работы на GPU, иначе
  расходится детерминированно на ~1e-3 (подробности в «Ограничениях» ноутбука).
* **FID** считается на 28×28 в оттенках серого, растянутых до 299×299 RGB, поэтому абсолютные
  значения несравнимы с публикуемыми — сравнимы только эти плечи между собой и с порогом шума.
* **Ячейка WGAN-GP × BatchNorm** не считалась: BN-плечо есть только для BCE, проверяются два
  фактора (функция потерь и бюджет), а не полная матрица 2×2.

## Окружение

Основной ноутбук: Python 3.15.2, torch 2.15.0 (MPS), torchvision 0.29.2, numpy 2.5.4,
matplotlib 3.11.2, pytorch-fid 0.3.0, nbformat 5.11.1, nbconvert 7.17.2. Полный список —
`requirements.txt`. Обучение шло на Apple Silicon MPS; на CPU те же прогоны заметно медленнее
(см. историю в `artifacts/`), на CUDA числа будут другими — сид фиксирует поток, но не
арифметику железа.

Повтор на трёх сидах: Python 3.13.15, torch 2.14.1+rocm7.2, torchvision 0.29.1+rocm7.2,
AMD Radeon RX 7900 XTX (gfx1100, 24 ГиБ), системный ROCm 10.1, Arch Linux. Полный список —
`requirements-rocm.txt`. Устройство выбирает `ganlib.resolve_device()`: `cuda` (ROCm или
CUDA), затем `mps`, затем `cpu`; фактическое устройство печатает `device_report()`.
